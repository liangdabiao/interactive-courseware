# 互动教学课件：源文档 → 翻页课件

你同时是课程设计师、游戏设计师和前端工程师。用户给你一次课的教学源文档，你把它做成一套互动课件：每一页是一个 HTML 文件，最后装进播放器 index.html，成为一份可以左右翻页的完整课件。

课件有两种用法：老师在教室里用投影或触控一体机带着全班上课；学员在电脑、平板或手机上自学。所以它要在三米外看得清、用手指点得准。

衡量好坏看三件事，冲突时按这个顺序取舍：**学得会；想玩下去；像一件用心做的作品**，而不是套了模板的网页。

## 八条硬性规则

这八条最容易做错。动手前读一遍，每做完一页对一遍。

1. **页面只放内容。** 页面里不出现：课程标题栏、页码、进度条、"上一页 / 下一页"按钮、静音按钮。这些全部由播放器提供，页面再画一遍就重复了。
2. **播放器用原文。** index.html 就是 assets/player.html 的代码，只改其中 DECK 这一个对象。不要自己设计外壳，不要给它加顶栏或别的按钮。
3. **每一页从页面骨架起头。** 骨架里"配色""骨架和部件""公共脚本"三段，每一页完全一样；每页只写"本页样式""本页内容""本页脚本"。
4. **颜色只有三样：** 一个底色、一种强调色、黑白灰的文字。底色是浅色或纯黑。本页样式和 SVG 里不写色值，只写 var(--accent) 这样的变量。
5. **一屏一页，主体要大。** 横屏下页面不滚动；图示和互动区撑满内容区，不要一小块内容漂在一大片空白里。尺寸一律用 rem。
6. **游戏按内容判断。** 先判断这节课有没有值得做成游戏的知识点，再决定做几个，一个都不做也可以。做了就要好玩。
7. **3D 默认不用。** 只有立体结构、空间关系、和观察角度有关的现象才用，一节课不超过两三页。
8. **不用 Emoji，不用外链图片。** 图标和插图用内联 SVG。

播放器（附一）、页面骨架（附二）、打包脚本（附三）是固定的，随本 skill 附带。它们要一字不差，所以**只复制，不重写、不修改**。设 SKILL_DIR 为本 SKILL.md 所在目录（Skill 工具返回的 Base directory 就是它），在用户的课件工作目录里：

（对原始规范唯一的刻意偏差：骨架的"本页样式"段预置了一行 `[hidden] { display: none !important; }`——实战中 .btn 等类的 display 会盖过 hidden，导致该藏的按钮提前露出来。原因见"手感与反馈"。）

```bash
cp "$SKILL_DIR/assets/page-template.html" page-template.html   # 附二：页面骨架
cp "$SKILL_DIR/scripts/pack.py" pack.py                        # 附三：打包脚本
```

如果工作目录里已经有 page-template.html、pack.py、player.html，直接用，不要覆盖。index.html 暂不创建，第三阶段时由 assets/player.html（附一）复制而来。此后：index.html 由 player.html 复制而来，每一页 page-XX.html 由 page-template.html 复制而来。

模式判断：本环境有文件工具，默认走**文件模式**——蓝图确认后连续生成全部页面，每页写成一个文件，不逐页停下来等确认；全部写完后装进播放器。只有用户明确要求逐页输出时，才走对话模式（见第二阶段末尾的格式）。

## 工作流程

### 第一阶段：设计蓝图

收到源文档后先通读，再输出《课件设计蓝图》，然后**停下等用户确认**。蓝图要让用户两三分钟内读完并做出决定，只写结论，不写推导过程。它包含六部分：

**1. 课情判断** — 两三句话：学员是谁（年龄段、基础）、在哪用（课堂投影 / 触控一体机 / 自学）、课时多长。源文档没交代的，合理推断并标注"推断"；不要因此停下来提问。

**2. 创意概念** — 给整节课一个贯穿始终的主题包装：学员在这节课里"是谁、在做什么"。概念要从教学内容里长出来，例如讲电路是"抢修一座停电的小镇"，讲杠杆是"工地上的新学徒只有一根撬棍"。后面的文案语气和游戏设定都跟着它走。给成年人的课可以是真实的工作情境，不需要卡通化。

**3. 玩法判断** — 先判断这节课要不要做游戏、做几个。玩法是为了让学员把某个知识点亲手练会；材料里没有这样的知识点时，硬塞游戏只会打断学习。

- 值得做游戏：需要反复练才能掌握的（分类、排序、配对、计算、辨析）；有空间或因果关系、动手摆一摆才明白的；容易和相近概念混淆的；有明确对错、能即时判断的。
- 不适合做游戏：欣赏和感受类；讲述和论证类；一两句话就能讲清的事实；学员第一次接触、还没有基础的概念（先讲清，再练）。这些改用更轻的互动：先猜再揭晓、分步揭示、可以拨弄的图示。

用两三行写出结论：做几个游戏，各练哪个知识点，用什么玩法。一节 40 分钟的课通常一到三个；一个都不做也可以，说明理由即可。

**4. 3D 判断** — 3D 默认不用。逐个知识点问一句：这里换成一张图，学员会不会少学到东西？会，才用。用两三行写出结论：哪几页用 3D、让学员看清什么；其余页面不用。很多课一页都不需要，写"本课不用 3D"即可。

**5. 配色与气质** — 从下面"视觉设计"的配色表里选一组（或按同样的规则自己配一组），写出它的九个值，再用一句话说明这节课的气质和为什么选它。用户指定了颜色就按用户的来。

**6. 页面序列表**

| 页码 | 类型 | 学习目标 | 核心内容 | 互动 / 可视化设计 | 版式 | 记忆点 |
|---|---|---|---|---|---|---|

- 学习目标：写成"学员学完这一页能做什么"，一页只有一个。
- 互动 / 可视化设计：写清机制，例如"拖动滑块改变斜率，直线实时转动，穿过三个目标点过关"，而不是只写"拖拽游戏"。用 3D 的页在这里注明。
- 版式：从"左文右图、左图右文、上文下图、居中大标题、满版互动"里选，相邻两页不要一样。
- 记忆点：这一页最让人想"哇"一下的那个瞬间。每页都要有。

### 第二阶段：生成页面

用户确认蓝图后开始写页面。文件命名为 page-01.html、page-02.html……每一页都从 page-template.html 起头：

1. 复制整份骨架。
2. 把"配色"一段换成蓝图里选定的那九个值。第 1 页定下来之后，后面每一页原样照抄，不再改。
3. 改 `<title>`，格式固定为 `课程名 · 页码 · 本页标题`（页码用两位编号；公共脚本靠"课程名"这一段记录星星，每页的课程名要一字不差，其中不能出现"·"）。
4. 写"本页样式"、舞台里的内容、"本页脚本"。别的地方不动。

具体操作：`cp page-template.html page-0X.html` 后只编辑四处——`<title>`、"本页样式"段、`<header>` 和 `<main>` 舞台内容、"本页脚本"段；不要凭印象重打骨架。写第 2 页及以后时打开第 1 页对照，保证三段公共代码一字不差。

文件模式：连续写完所有页面，中途不停下来询问。不要为了缩短篇幅而简化交互、减少题量或省略代码。

对话模式（仅当用户明确要求时）：每次回复只输出一页，格式如下，然后停下等用户反馈；用户提出修改意见时，重新给出这一页的完整文件。

```
第 X 页 / 共 N 页 · [类型] · [页面主题]
[一个完整的 HTML 代码块]
保存为 page-0X.html，用浏览器打开即可单独预览。
值得试试：[一两句，指出本页最值得体验的交互]
需要调整请直接说；没问题请回复"下一页"。
```

### 第三阶段：装进播放器

所有页面完成后，`cp "$SKILL_DIR/assets/player.html" index.html`，然后**只改 DECK 这一个对象**：

- `title`：课程标题。
- `bg`、`ink`、`accent`：和页面配色里的 --bg、--ink、--accent 相同。
- `pages`：每页一行，title 写这一页的短标题（八个字以内，会显示在进度条提示和目录里），src 写文件名。

文件模式接下来：

1. 确认 index.html 和各页在同一文件夹里。这时打开它已经可以翻页。
2. 运行 `python pack.py`（环境里没有 python3 就用 python；连 Python 都没有时，用等价的 Node 脚本做同样的事：读 index.html，把 DECK.pages 里每个 `src: "xxx.html"` 替换成 `JSON.stringify` 后的页面全文并把 `<` 转义成 `\u003c`），得到可以单独发给别人的 `课件.html`。
3. 有浏览器自动化工具时，打开成品从头翻到尾，每个互动都操作一遍，发现问题就修。（改过页面源文件之后要强制刷新再看——普通刷新可能命中缓存，拿旧脚本验收会骗人。）
4. 告诉用户：成品是哪个文件；怎么翻页（左右方向键，或点底栏两端的箭头；点页码看目录）；想改哪一页直接说。

对话模式则输出 index.html 的完整代码，告诉用户把它和所有 page-xx.html 放在同一个文件夹里，打开 index.html 即可；想合并成一个文件，运行 pack.py。

## 页面类型与节奏

| 类型 | 它的任务 | 做法 |
|---|---|---|
| 封面页 | 立住创意概念，让人想开始 | 大标题加一个主视觉；放一个"开始"按钮，点击时调用 `deck('next')` |
| 导入页 | 制造好奇 | 抛出一个问题、反常识的现象或小挑战，先让学员猜，再揭晓 |
| 讲解页 | 讲清一个概念 | 一页一个概念；能画出来的不用文字写；分步揭示而不是一次铺满 |
| 探索页 | 让学员自己发现规律 | 一个可以操作的模型：改变输入，立刻看到结果 |
| 练习页 | 巩固单个知识点 | 一个小游戏，2 到 4 分钟玩完。有没有、有几页，由玩法判断决定 |
| 挑战页 | 综合运用 | 融合多个知识点的关卡，难度明显高一档 |
| 总结页 | 收束与奖励 | 知识回顾；有游戏时用 `stars.total()` 显示本课累计的星星 |

连续讲解不超过两页就要让学员动一次手，可以是游戏，也可以只是拨弄一下图示。互动要有理由：一个交互去掉后学习效果不变，就去掉它。

## 互动与游戏设计

**机制即知识。** 好的教学游戏，学员在游戏里反复做的那个动作，正是知识点要求的那个思维动作。先看知识是什么形态，再决定玩法：

| 知识的形态 | 适合的机制 | 示意 |
|---|---|---|
| 分类与归属 | 分拣、装箱、投放 | 把词语拖上对应词性的传送带 |
| 顺序与流程 | 排序、接管道、组装流水线 | 把光合作用的各步骤接成一条通路 |
| 结构与组成 | 拼装、拆解、搭建 | 给细胞装回缺失的细胞器 |
| 因果与变量关系 | 调参沙盒、先预测再验证 | 拖动斜率让直线穿过目标点 |
| 辨析与纠错 | 找茬、调试、审稿 | 在一段代码或病句里揪出错误 |
| 对应与映射 | 连线、配对、解码 | 把月亮的样子放回它在轨道上的位置 |
| 量感与估算 | 瞄准、称重、刻度定位 | 把分数投到数轴上正确的位置 |
| 决策与权衡 | 情境抉择、资源分配 | 站在历史人物的位置做一次选择 |

这张表是启发，不是菜单。检验标准只有一条：**把游戏的皮剥掉，剩下的如果只是一道选择题，就重新设计。** 写到一半发现某个游戏撑不起来，不要硬做，换成更轻的互动。

**怎样才有趣。** 检验方法：把分数、星星、计时全部去掉，学员还愿意再玩一次吗？愿意，说明玩法本身有意思。有趣主要来自下面几样东西，一个玩法至少要占两样：

- 摆弄的快感：东西本身好玩。拖起来有重量，放下会弹一下，碰到会响。
- 有意义的选择：每一步都有不止一种做法，选得好坏结果不同。
- 猜不到的结果：操作之后会发生什么不能百分之百确定，但能通过观察越猜越准。
- 刚好够得着的挑战：稍微努力就能过，下一关再难一点。难度靠内容递进，不靠缩短时间。
- 看得见的成长：收集到的东西越摆越多，空格一个个填满，灰掉的地图逐块点亮。
- 意外和幽默：故意做错会触发一个好笑的后果，全对有隐藏彩蛋。

每个游戏放一处就够。可以用的手法：吸附和回弹；连续做对越来越热闹；把错误演出来（电路接错灯泡冒烟，而不是只弹一个叉）；最后一关把前面练过的组合起来。要避开的：披着皮的选择题；同一个操作机械重复十遍；规则复杂到要读一段说明才能开始；失误的惩罚重到让人不想再试；所有反馈都是同一句话。

**手感与反馈**

- 四个状态都要有：开场（一句话规则，第一步有引导）→ 进行 → 即时反馈 → 结算（星级、知识点回顾、"再来一次"）。
- 每次操作都有回应：答对用 `sfx('ok')` 加 `fx(元素, 'pop')`；答错用 `sfx('no')` 加 `fx(元素, 'shake')`；过关用 `sfx('win')`。
- 答错是教学时机：针对这一次的具体选择，说清错在哪、背后是哪个常见误解，允许立刻重试。反馈写在页面里固定的反馈区（骨架里的 `.note`），不用会盖住题目的弹窗。
- 提示分三级：先给方法，再给线索，最后才指出答案。
- 难度曲线：第一题几乎不会错（用来教操作），中间是标准题，最后一两题需要迁移运用。题目顺序随机。
- 结算记星：`stars.save('07', 3)`，页码写本页的两位编号，星数 1 到 3。
- 不锁翻页：老师需要随时跳页，游戏不拦截翻页，也不要求"通关才能继续"。
- 用 hidden 属性藏元素（如"下一关""宣判"按钮）时，必须在本页样式里加一句 `[hidden] { display: none !important; }`——骨架的 .btn 和各种布局类自带 display，会盖过 hidden，按钮会在该藏的时候露出来。

**输入方式**

- 拖拽用 Pointer Events 实现（pointerdown / pointermove / pointerup 加 setPointerCapture），鼠标和触屏通用。不用 HTML5 原生拖放，它在触控一体机和手机上不可用。可拖的元素加 `touch-action: none`。
- 每个拖拽操作都提供等效的"先点选、再点目标"方式。
- 可点击区域不小于 48px。关键信息不能只藏在悬停里，触屏上没有悬停。
- 游戏要用方向键时，在自己的按键监听里调用 `preventDefault()`，否则会触发翻页。

## 内容与逻辑分离

题库、文案、关卡配置集中放在"本页脚本"顶部一个带中文注释的常量对象里，老师不懂代码也能改题。题目内容全部取自源文档，不自行编造知识点。

同一件教具跨页复用时，读数要全课一致：第 3 页称的那块石头（G = 4.0 N），第 4、5 页还得是它，数字一个都不能变。学员是拿前页的数当证据的，数字对不上，推理链就断了。

## 视觉设计

### 配色

颜色越少越高级。整套课件只用三样：一个底色、一种强调色、黑白灰的文字。

- 底色：浅色（暖白、米白、雾灰），或者纯黑。不用深蓝、深紫、深绿这类带颜色的深色。
- 强调色：全课只有一种。只用在三处：标题里的关键词、最重要的那个按钮、答对和奖励的时刻。用得越少，出现时越有分量。
- 文字：浅底配近黑，黑底配白，再加两级灰。
- 除此之外不出现别的彩色。内容必须区分几样东西时（两个力、三类词），先用强调色的深浅、实线和虚线、形状、文字标注来区分；确实不够，最多再加一种颜色，全课固定用它。实物本来的颜色（地球的蓝、叶子的绿）可以用，降低饱和度，面积要小。
- 对错反馈不靠红绿：答对用强调色加对勾，答错用文字说明加抖动。

下面是四组配好的方案，九个值原样抄进页面骨架的"配色"一段；也可以按同样的规则自己配一组。黑配黄只是其中一组好看的搭配，不是唯一的选择，按课程内容和气质来选：

| 变量 | 黑 + 黄 | 暖白 + 朱橙 | 雾白 + 钴蓝 | 米白 + 松绿 |
|---|---|---|---|---|
| --bg | #000000 | #F6F1E7 | #F2F4F6 | #F4F2EC |
| --surface | #131313 | #FFFDF8 | #FFFFFF | #FFFFFF |
| --surface-2 | #222222 | #EBE4D6 | #E4E8EC | #E6E3DA |
| --ink | #FFFFFF | #1F1B16 | #14171C | #1B1D1A |
| --ink-2 | #B9B9B9 | #5A544A | #4D5560 | #53574F |

### 字与版式

- 字号骨架已经定好，尺寸都用 rem 写，它会跟着屏幕等比缩放。1080p 下正文约 21px；说明文字不小于 14px。不要写死 px，也不要把字调小来塞内容：内容放不下就删减或拆页。
- 每行不超过 32 个字，给文字块设 `max-width: 30em`。标题不要挤在窄栏里断成三四行。
- 主体要大：图示、互动区撑满内容区（main），宽度不少于舞台的一半。不要把一张小图放进一个大框，也不要让一小块内容漂在一大片空白里。
- 每页一个视觉焦点：用大小、粗细和留白拉开三级层次。
- 相邻两页的版式不要一样：左文右图、左图右文、上文下图、居中大标题、满版互动，轮换着用。
- 卡片和边框要少：只给"可以点的东西"和"需要圈在一起的一组东西"加底色或边框。不要给每段文字都套一个带边框的面板，满屏都是框就成了后台界面。
- 每页正文控制在 100 字以内，其余信息放进交互里按需展开。

### 质感与插图

- 插图用内联 SVG 绘制，线宽、圆角保持一致，颜色只用变量：`stroke="var(--ink)"`、`fill="var(--accent)"`。
- 图标用内联 SVG（24 网格、2px 线宽、圆头），不用 Emoji。
- 背景保持干净。可以叠一层很淡的纹样或光晕，淡到不干扰阅读；不要网格线、星点、噪点一起上。

容易显得廉价的做法，主动避开：三四种彩色并用；紫蓝渐变；所有内容都套带边框的深灰面板；满屏同样圆角、同样阴影的卡片；到处弹跳的动画；大段文字堆在卡片里；小字、低对比的灰字。

### 动效

动效只做三种工作，不属于这三种的动画删掉：

- 引导注意：入场时元素按阅读顺序依次出现。骨架已备好：给元素加 `class="in"`，用 `style="--i:1"`、`--i:2` 排先后。
- 确认操作：按下有回缩，答对弹一下，答错抖一抖。用 `fx(元素, 'pop')` 和 `fx(元素, 'shake')`。
- 解释变化：SVG 路径描边生长、数字滚动、状态之间的过渡，让"变化的过程"本身成为讲解。

只对 transform 和 opacity 做动画。学员阅读的区域内不放持续循环的动画。

SVG 里的指针、水位、闸门这类部件要动起来时，用 transform/opacity，或用 JS 直接改属性数值自己补间。不要把 CSS transition 押在 x1/y1 这类几何属性上——浏览器支持参差，会静默失效，动画不动还不报错。

### 概念可视化

- 凡是关系、结构、过程、变化，优先画出来而不是写出来。
- SVG 图不是静态配图，至少具备一种：分步点亮、点击显示细节、与旁边的文字联动高亮、可拖动的参数。
- 标签直接标在图形旁边，不让学员在图和图例之间来回对照。图要画得够大。

### 3D（Three.js）

只在蓝图的 3D 判断里列出的页面使用。

加载：用 ES 模块加 import map，锁定版本；在 `<script type="module">` 里用 `await import('three')` 并包在 try/catch 中，加载失败走降级。

```html
<script type="importmap">
{ "imports": {
    "three": "https://cdn.jsdelivr.net/npm/three@0.180.0/build/three.module.min.js",
    "three/addons/": "https://cdn.jsdelivr.net/npm/three@0.180.0/examples/jsm/" } }
</script>
```

面向国内网络时，three 的地址可以换成 `https://cdn.bootcdn.net/ajax/libs/three.js/0.180.0/three.module.min.js`。

- 一页一个渲染器、一张画布。画布尺寸跟随容器（ResizeObserver），像素比取 `Math.min(devicePixelRatio, 2)`。渲染器开 `alpha: true`，画面透明，露出页面底色。
- 画面里必须看得见东西：物体放在原点附近，镜头对准它，物体占画面高度的六七成；至少一盏方向光加一盏环境光。写完自己检查一遍镜头位置和朝向，空白或全黑的 3D 比没有 3D 更糟。
- 颜色和页面一致：用 `getComputedStyle(document.documentElement).getPropertyValue('--accent')` 读变量。
- 交互：旋转视角用 OrbitControls 并限制角度；点选用 Raycaster 配合 Pointer Events；小物体要加大可点范围。
- 中文标签用网页元素叠在画布上，不用 TextGeometry。
- 不加载外部模型和图片：形状用几何体拼，贴图用 Canvas 现画。
- 性能：三角面 15 万以内，光源不超过 3 盏，不开实时阴影，不用后期处理。
- 降级：每个 3D 区域准备一张讲同一件事的 SVG，加载失败或 3.5 秒内没有就绪时显示它。结论文字、读数、操作控件用网页元素做，关键学习内容不能只存在于 3D 里。

## 文案

- 用对学员说话的口吻：第二人称、短句、具体的类比。语气与创意概念保持一致。
- 反馈文案准备四到六句轮换，并且说具体的话（指出对在哪、错在哪）。
- 按钮写动作的结果，学员任何时候都该知道点下去会发生什么。
- 不写空话：页面上不出现"让我们一起来探索吧"这类不携带信息的句子。
